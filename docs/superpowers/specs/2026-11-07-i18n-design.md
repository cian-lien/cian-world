# 项目多语言接入设计

用户已确认：简体中文与英文，覆盖全部界面、个人资料及项目介绍；文章保持原语言，后续单独扩展译文。

采用 i18next + react-i18next + TypeScript 词典，保留 React/Vite/Hash 静态站点。相比自建 Context 字典，复用现成的插值、复数、回退机制，集中维护文案；不迁移框架或引入服务端。

- 词典同步初始化，React、R3F 和 drei 独立 DOM 根共用实例；类型检查 key，测试词典结构与插值。
- 语言优先级：URL → 手动选择的 localStorage → 浏览器首个受支持语言 → zh-CN。中文区域变体归 zh-CN，英文归 en，不支持的值忽略。
- `?lang=en#/computer`；replaceState 保留其他参数、子路径、Hash 及历史状态，不新增语言切换历史条目。后退前进按目标 URL 恢复语言，存储禁用不阻止使用。
- HUD 和日记本各提供语言选择器（简体中文 / English），支持键盘、沿用样式，窄屏换行，烘焙参考模式隐藏 HUD。根据后续 DESIGN.md 样式调整要求，选择器改为按钮与 listbox，并通过页面浮层避免被日记本滚动区域裁切。
- 语言切换保留场景、灯光、镜头、窗口、当前文章和终端输入。命令名称不变，终端历史保留执行时的文本，欢迎文字及新输出使用当前语言。
- `Locale`、`useLocale()`、`setLocale(locale)`、`getSite(locale)` 为接入接口。资料、项目、书签的翻译与共用数据按稳定 ID 组织，禁止数组下标关联译文；姓名、品牌、URL、技术栈共用，翻译不增加事实。
- 保持 Post/posts 接口和所有 Markdown 内容、元数据、slug、顺序、草稿规则。英文阅读界面说明文章为中文，内容标记 lang=zh-CN；不增加文章译文、筛选或回退系统。
- README 与多语言文档说明选型、策略和维护。无自动翻译、CMS、多语言 SEO、模型修改或整体移动端改版。

验收：Vitest 语言检测/URL/词典/插值/复数/资料一致性；浏览器覆盖所有视图、持久化、历史、存储禁用、键盘、英文窄屏和状态保留；typecheck/build/diff 均通过，文章文件无差异。
