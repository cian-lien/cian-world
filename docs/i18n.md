# 多语言实现与维护

支持简体中文（`zh-CN`）和英文（`en`）。房间提示、加载文字、RoomOS、终端、日记本界面、个人资料及项目介绍均有双语版本。文章内容保持原文，当前三篇都是中文。

## 技术选型

采用 **i18next + react-i18next + TypeScript 词典**，保留 React 18、Vite、Hash 路由及静态部署。

| 方案 | 取舍 |
| --- | --- |
| TypeScript 字典 + React Context | 无新增依赖，但插值、复数、语言回退需要自行维护。 |
| i18next + react-i18next（采用） | 提供翻译 Hook、插值、复数、回退及类型化 key；统一普通页面、3D 提示与电脑桌面的语言。 |
| 迁移框架和路由 | 超出此次界面国际化范围；未来需要语言专属 SEO 页面时另行评估。 |

参考：[React 接入](https://react.i18next.com/latest/using-with-hooks)、[TypeScript 类型扩展](https://www.i18next.com/overview/typescript)、[回退机制](https://www.i18next.com/principles/fallback)。

两种语言的界面词典随代码静态打包，在 React 渲染前同步初始化，不请求翻译服务。`initReactI18next` 注册共用实例，使 React、R3F 和 drei `Html` 创建的独立 DOM 根订阅同一语言变化。切换不依赖整页刷新，也不按语言为 Canvas 或窗口设置新 key。

## 语言规则与地址

优先级：**URL 的 `lang` → 保存的手动选择 → 浏览器偏好中的首个受支持语言 → 简体中文**。

- `en-US`、`en-GB` 等归为 `en`；`zh-TW`、`zh-HK` 等归为 `zh-CN`。本期只提供简体中文译文。
- 不支持的语言值被忽略，继续查找下一个来源。
- 初始化和切换时，将生效语言写入 `?lang=zh-CN` 或 `?lang=en`，保留其他参数、子路径、编码后的 Hash 及 `history.state`。
- 使用 `replaceState`，语言切换本身不增加历史记录。前进、后退到其他语言的地址时按该 URL 恢复语言。
- 手动选择保存至 localStorage 的 `room-blog.locale.v1`。存储被禁用时不影响初始化和切换，刷新仍可从 URL 恢复。

```text
?lang=zh-CN#/
?lang=en#/computer
?lang=en#/diary/hello-room
?bake=live&lang=en#/diary/hello-room
```

旧 `#/diary/<slug>` 链接继续可用，首次打开按优先级解析语言后补齐查询参数。文章链接继续使用相同 slug，Hash 导航会保留查询参数。

切换后同步 `<html lang>`、界面和视图标题；文章页的标题仍用原文文章名。终端日期及桌面时钟使用当前语言的 `Intl` 格式，文章发布日期继续显示原有 `YYYY-MM-DD`，不经过时区转换。

## 接口和词典维护

`src/i18n/locale.ts` 负责受支持语言、纯语言检测及 URL 处理；`src/i18n/index.ts` 初始化实例并提供：

```ts
type Locale = 'zh-CN' | 'en'
useLocale(): Locale
setLocale(locale: Locale): void
```

组件用 `useTranslation()` 取得 `t`，例如 `t('diary.count', { count: posts.length })`。`src/i18n/resources.ts` 中按 `hud`、`scene`、`desktop`、`terminal`、`diary` 分组维护完整句子。`CustomTypeOptions` 检查 key，英文词典用映射类型检查结构，测试检查 key、非空翻译和插值变量一致性。

计数使用 i18next 的复数后缀，例如 `count_one` / `count_other`；动态值使用 `{{count}}` 等占位符。不要在组件中拼接句子片段；译文不作为 HTML 注入，普通文本由 React 转义。日期时间使用原生 `Intl`。

语言选择器使用可访问的按钮与 listbox，按 `DESIGN.md` 呈现纸色胶囊按钮、深棕描边、硬阴影及明黄选中状态。HUD 和日记本各有一个入口；菜单通过 portal 呈现在页面浮层，避免被日记本的滚动区域裁切，跟随按钮定位并保持在视口内。窄屏 HUD 允许换行，日记本使用带完整可访问名称的紧凑图标按钮，烘焙参考模式继续隐藏 HUD。

方向键、Home/End 可移动选项焦点，回车或空格确认；Esc 只关闭菜单并将焦点返回按钮，Tab 关闭菜单后继续正常焦点移动。点击外部也会关闭。焦点轮廓、44px 点击区域和减弱动态模式沿用设计规范。

## 个人资料、项目和书签

`src/content/site.ts` 将共用身份、技术栈和链接与描述性内容分开，翻译保存在对应记录内部：

```ts
{
  id: 'example-b',
  name: { 'zh-CN': '示例项目 B', en: 'Example project B' },
  desc: { 'zh-CN': '中文介绍', en: 'English description' },
  tech: ['Node.js', 'PostgreSQL'],
  url: 'https://github.com/',
}
```

`getSite(locale): Site` 返回适合原有组件使用的扁平字段；默认中文的 `site` 导出继续提供共享品牌及兼容配置。项目和书签使用稳定的 `id` 作为 React key，不能按语言改变，也不通过两个数组的下标配对译文。

新增记录时在同一处补齐中英文；共用名称可直接写字符串，需翻译时写完整的语言记录。姓名、品牌、URL 和技术名称共用，译文保留原意，不添加经历或能力。

## 文章及状态保留

本期不修改 `content/posts/`，不修改 `Post` / `posts` 接口及 Markdown 解析过程。标题、摘要、标签、正文、slug、排序和草稿规则保持原样；不按界面语言过滤文章，也不建立译文回退系统。

英文日记界面说明文章当前为中文，目录中的文章名和文章内容容器标记 `lang="zh-CN"`。后续如果引入其他原文语言或文章译文，需要单独设计文章语言元数据及关联方式，再更新这些标记。

语言切换保留日夜、台灯、镜头、窗口数量/位置/层级、当前文章及终端输入。终端命令仍为 `help`、`whoami`、`ls`、`cat <N>` 等英文命令；欢迎文字和后续输出跟随当前语言，历史输出保留执行时的文本。`ls` 和 `cat` 始终读取同一份原文文章列表。

## 验证与部署

```bash
pnpm test
pnpm typecheck
pnpm build
```

Vitest 覆盖语言检测、非法值、区域匹配、URL 保留、词典结构、插值、英文复数及资料共用数据一致性。浏览器验收覆盖三个视图、刷新、旧链接、前进后退、状态保留、键盘选择、英文窄屏和存储禁用。

发布仍只需部署 `dist/`，不需要新增服务、密钥或路由重写。当前 Hash SPA 没有按语言预渲染的 SEO 页面，也未新增语言专属 `hreflang`。自动翻译、文章译文、模型调整和移动端整体适配均不属于此次接入。
